# Backend — Render

This folder contains the Express API (`src`), PostgreSQL schema/migrations (`db`), request validation (`api-zod`), and OpenAPI/code generation (`api-spec`). API routes retain their `/api` prefix.

Create a **Web Service** on Render from this repository, or use the root `render.yaml` Blueprint. Keep **Root Directory blank** (repository root) because pnpm uses the root workspace and lockfile. Use:

- Runtime: Node; version 24.14.1 (root package metadata pins pnpm 10.34.5).
- Build Command: `pnpm install --frozen-lockfile --prod=false && pnpm run build:server`
- Start Command: `pnpm run start:server`
- Health Check Path: `/api/healthz`

The install command includes build dependencies even when `NODE_ENV=production`.

The server binds to `0.0.0.0` on Render's `PORT`. The Blueprint provisions a web service only; connect a durable PostgreSQL database separately. Set these **Render** environment variables:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Your PostgreSQL connection string, including the provider's required TLS options |
| `BETTER_AUTH_SECRET` | Stable random secret of at least 32 characters; generated by the Blueprint |
| `BETTER_AUTH_URL` | Exact Vercel/custom **frontend** HTTPS origin, e.g. `https://your-journal.vercel.app`, without `/api` |
| `NODE_ENV` | `production` |

Before first use, provision a new empty database with `pnpm --filter @workspace/db push` using that database's connection string. Review Drizzle's proposed schema changes. For existing databases, back up first and follow the numbered migrations and legacy ownership instructions in the root README. Build/start commands deliberately do not push or reset the database.

After Render supplies its `https://...onrender.com` URL, set that URL in the root `vercel.json` API rewrite and deploy the frontend. Requests arrive via Vercel with the frontend Origin and session cookie; auth and journal writes validate that origin. Keep one canonical frontend origin matching `BETTER_AUTH_URL`; preview deployments need their own matching backend/database configuration for authenticated use.

No permissive CORS or third-party cookies are used. Visiting Render's health URL directly works; use the frontend URL to sign in and manage the journal. Preserve the auth secret and database across redeploys to retain accounts/data.
