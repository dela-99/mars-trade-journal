# Server

Independent Express backend. Install and run commands **inside this folder**. Database and API validation modules are ordinary source under `src/db/` and `src/api-zod/`.

## Render settings

| Setting | Value |
| --- | --- |
| Service type | Web Service, Node |
| Root Directory | `server` |
| Build Command | `pnpm install --frozen-lockfile --prod=false && pnpm run build` |
| Start Command | `pnpm run start` |
| Health Check Path | `/api/healthz` |

The root `render.yaml` uses these settings. No files outside `server/` are required to install, build or run this backend. Node 24 and pnpm 10.34.5 are pinned locally. Build tools are installed even when NODE_ENV=production.

## Required environment

Set these variables in the Render **backend service → Environment**. Copy `.env.example` for local configuration; actual credentials must remain private.

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | A durable PostgreSQL connection URL; use Render's internal URL when the database and service share an account/region |
| `BETTER_AUTH_SECRET` | Stable random secret of at least 32 characters; generated by the Blueprint |
| `BETTER_AUTH_URL` | Final Vercel/custom **frontend** HTTPS origin, e.g. `https://your-app.vercel.app`, without `/api` |
| `NODE_ENV` | `production` |

Render supplies `PORT`; Express binds to `0.0.0.0`. For local development set `PORT=3001` and `BETTER_AUTH_URL=http://localhost:3000`. Local commands inherit environment variables from the shell; they do not load `.env` automatically.

## Database initialization

The Blueprint defines the server only. Connect PostgreSQL separately. For a **new empty database**, with DATABASE_URL set:

```bash
pnpm run db:push
```

Review the schema proposed by Drizzle. For an existing database, back it up and apply the numbered SQL migrations under `db/migrations/` as described in the root README. Builds do not alter database tables. Convex is not used by this PostgreSQL adapter.

## Local commands

```bash
pnpm install --frozen-lockfile --prod=false
pnpm run typecheck
pnpm test
pnpm run build
PORT=3001 pnpm run start
```

Verification/operator scripts live in `scripts/`. Run `node scripts/verify-account-import.mjs` with DATABASE_URL set and a frontend/API proxy at JOURNAL_TEST_ORIGIN (default http://localhost:3000). It creates disposable test accounts and removes them. `node scripts/assign-legacy-journal.mjs owner@example.com --confirm` assigns unowned legacy rows after verifying the intended account.

The optional `pnpm run codegen` updates API validation here and the browser client in the sibling frontend folder; both projects are needed only for that development command. Hosting builds never run code generation.

After Render provides its URL, set the frontend API rewrite to that URL. Authenticated requests must come through the frontend origin matching BETTER_AUTH_URL. Use the same database and secret across redeploys to retain accounts/data. Preview frontends need their own matching auth/backend configuration.
